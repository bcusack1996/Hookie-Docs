A **project** is the unit everything else in Hookie belongs to. Endpoints, ingest keys, datasets, rules, destinations, sources, triggers, workflows and deliveries all live in exactly one project. A project belongs to a **workspace**, which is your account.

Every workspace starts with a project called **Default**. If you are just trying Hookie out, use it and ignore projects entirely.

## When to add a project

Use projects to keep things apart that should not see each other: production and staging, or two products with their own senders and receivers. Rules only route within their project, a destination only receives its own project's records, and an ingest key only sends into, and streams from, its own project.

## Create a project

On **Projects**, choose **Create a project**. Enter a **Name** and pick a **Type**:

| Type | What you get |
| --- | --- |
| **Webhook** | Collect events from endpoints you publish. Hookie adds one endpoint for you, named after the project, that stores into the dataset `default`. |
| **AI trigger** | Run a model against events as they arrive. Nothing is added for you. |

The new project opens on its **Endpoints** tab. For a Webhook project, the endpoint Hookie added is marked **new**.

The type is a starting template, not a restriction. Any project can add any endpoint, key, source, trigger or workflow later.

Only workspace owners and admins can create projects. Developers and viewers don't see the button.

## Inside a project

Open a project to see its tabs:

| Tab | What it holds |
| --- | --- |
| **Overview** | Volume for the last 24 hours to 30 days, the pipeline at a glance, and the first endpoint's URL with a `curl` example. |
| **Endpoints** | Public URLs that receive events. See [Endpoints and ingest keys](/concepts/endpoints). |
| **Ingest keys** | Credentials for your own servers. |
| **Datasets** | The records stored in each dataset. See [Datasets and records](/concepts/datasets-and-records). |
| **Rules** | Routing for keyed events. See [Rules and mappings](/concepts/rules-and-mappings). |
| **Connections** | Destinations (outbound) and sources (inbound database polling). |
| **Workflows** | Multi-step [workflows](/workflows), their start triggers, and AI agents. |
| **Deliveries** | Every outbound attempt. See [Destinations, deliveries and retries](/concepts/destinations-and-deliveries). |
| **Observability** | Search across records, submissions, deliveries, AI runs and AI calls, trace any ID to its whole chain, and set up [Broadcast Logs](/broadcast-logs). |
| **Settings** | The project's name, slug and type; its configuration (export, import and clone); its [customer portal](/customer-portal) and [Data API](/data-api); and deleting the project. |

## The project slug

A project's slug is the second segment of every endpoint URL: `app.hookie.ai/{workspace}/{project}/{endpoint-slug}`. The Default project's slug is `default`. The **Overview** and **Settings** tabs show it.

## Export, import and clone

Under **Configuration** on a project's **Settings** tab:

- **Export JSON** and **Export YAML** download the project's configuration: endpoints, rules, destinations, AI agents, workflows, AI and cron triggers, and record views. Secrets, endpoint URLs and keys are never exported, and sources, WebSocket triggers and the customer portal aren't included.
- **Import configuration (JSON)** loads an export into the project. Imported endpoints get new URLs, and imported destinations get new signing secrets. Anything whose name already exists in the project is skipped, never overwritten. An endpoint that verifies its provider's signature is imported without the secret, so it refuses every request with `401` until you set the secret with **Edit…**. A YAML export is applied with `hookie apply` in the [CLI](/cli).
- **Clone project** copies the configuration into a new project. Owners and admins only.

Records, deliveries and other event data are not part of a configuration export. To download those, see [Delete, export and close](/data-deletion).

## Delete a project

On the **Settings** tab, **Delete this project** removes the project and everything in it. It cannot be undone, and only the workspace owner can do it. The Default project cannot be deleted, so there is always somewhere for events to land.
