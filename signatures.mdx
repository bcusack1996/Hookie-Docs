Every outbound delivery is signed with the destination's secret, a `whsec_`-prefixed value that Hookie generates when you create the destination. Verify the signature before trusting the payload.

You never have to write it down. The secret is encrypted at rest and masked in the console. The destination's **Reveal** button fetches it on demand for owners and admins only, and every reveal is written to your audit log. **Rotate** issues a new secret and shows it to you. The secret it replaces keeps signing for **24 hours**: every delivery in that window carries two signatures, one per secret, so your receiver keeps verifying while you update it (see [Rotating the secret](#rotating-the-secret)).

## The headers

Each delivery carries:

```http
Hookie-Signature: t=1718000000,v1=5f2b8c…e11a
Hookie-Event-Id: 9d3f2a10-…
Hookie-Delivery-Id: 4c7b…
Hookie-Hop: 1
```

- `Hookie-Signature`: `t=<unix>,v1=<hex>`, an HMAC-SHA256 (Stripe-style). For 24 hours after a rotation it carries a second `v1`: `t=<unix>,v1=<new>,v1=<previous>`.
- `Hookie-Event-Id`: the event ID. **Dedupe on this**, since delivery is at-least-once and unordered.
- `Hookie-Delivery-Id`: the specific delivery attempt, useful in logs.
- `Hookie-Hop`: how many times this event has passed through Hookie. If your service forwards the event into Hookie again, pass this header on: Hookie refuses an event at 8 hops, which stops a delivery loop.

Deliveries **never follow redirects**. A `3xx` answer is recorded as a failed attempt naming the `Location` it pointed to, and is not retried: a redirect means the destination URL is wrong, so update it rather than letting a signed event be forwarded somewhere you did not choose.

## What's signed

The signed string is `<t>.<raw body>`: the timestamp, a dot, then the exact request body bytes. Compute `HMAC-SHA256(secret, "<t>.<body>")` as lowercase hex and compare it in constant time with **each** `v1` in the header. Accept the request if any of them matches.

## Node.js

```js
const crypto = require("crypto");

// Verify a Hookie outbound webhook signature.
// header: the raw "Hookie-Signature" value ("t=<unix>,v1=<hex>[,v1=<hex>]")
// rawBody: the exact request body bytes (do NOT re-serialize the JSON)
function verifyHookie(secret, header, rawBody, toleranceSeconds = 300) {
  // v1 repeats during a secret rotation, so collect every one. (Object.fromEntries
  // would keep only the last, which is the PREVIOUS secret's signature.)
  const pairs = String(header ?? "").split(",").map((kv) => kv.split("="));
  const t = pairs.find(([k]) => k === "t")?.[1];
  const signatures = pairs.filter(([k]) => k === "v1").map(([, v]) => v);
  if (!t || signatures.length === 0) return false;
  if (Math.abs(Date.now() / 1000 - Number(t)) > toleranceSeconds) return false; // replay protection
  const expected = Buffer.from(crypto.createHmac("sha256", secret).update(`${t}.${rawBody}`).digest("hex"));
  return signatures.some((sig) => {
    const given = Buffer.from(sig);
    return given.length === expected.length && crypto.timingSafeEqual(given, expected);
  });
}
```

## Rotating the secret

Rotating is safe to do while deliveries are flowing:

1. Press **Rotate** on the destination (owner or admin). The new secret is shown to you.
2. For the next 24 hours every delivery is signed with **both** secrets, new first: `Hookie-Signature: t=1718000000,v1=<new>,v1=<previous>`. A receiver that accepts any matching `v1` (as the verifier above does) keeps working whichever secret it holds.
3. Update your receiver to the new secret at any point in that window. The destination shows when the previous secret stops signing.
4. Once every receiver is on the new secret you can press **Expire now** to stop sending the previous signature early; otherwise it stops on its own after 24 hours.

Rotating again inside the window replaces the older of the two, so at most two secrets ever sign a delivery. A receiver that briefly needs to accept both can also hold both secrets and check each.

## Express handler

```js
const express = require("express");
const app = express();

// Capture the RAW body — signature is over the exact bytes.
app.post("/hook", express.raw({ type: "*/*" }), (req, res) => {
  const raw = req.body.toString("utf8");
  const ok = verifyHookie(process.env.HOOKIE_SECRET, req.get("Hookie-Signature"), raw);
  if (!ok) return res.status(401).end();

  const eventId = req.get("Hookie-Event-Id"); // dedupe on this — delivery is at-least-once
  const event = JSON.parse(raw);
  // … handle event …
  res.status(200).end();
});
```

## Notes

- Verify against the **raw bytes**. Re-serializing the JSON will change the signature.
- Reject the request if the header is missing or `v1` doesn't match. Optionally reject old `t` values to limit replay.
- Always compare with a constant-time function such as `crypto.timingSafeEqual`.
- A destination's URL is fixed once created, and a signature is only meaningful against the URL it was sent to. To move a destination, create the replacement and delete the old one.
