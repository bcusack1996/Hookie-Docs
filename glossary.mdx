These docs use one name for each thing. Where the API, an MCP tool or the CLI uses another name for it, that name is listed under **Also appears as**. Use the name in the first column when you write about Hookie.

## Accounts and access

| Term | Meaning | Also appears as |
| --- | --- | --- |
| **Workspace** | Your account: its projects, plan, people and settings. The first segment of every endpoint URL is the workspace's slug. | `tenant` in API responses and errors |
| **Project** | The unit everything else is scoped to. Every workspace has a **Default** project. See [Projects](/concepts/projects). | `pid` and `project_id` in API paths |
| **Role** | What a person may do in a workspace: owner, admin, developer or viewer. See [Roles](/concepts/roles-and-agents). | `member`, a legacy read-only role |
| **Connected agent** | A coding agent, such as Claude Code or Cursor, that signed in as you over OAuth and calls Hookie's API through MCP. Opened from **Connect agent** in the console. | `agents` in the admin API; OAuth client |
| **Scope** | What you allowed a connected agent to do. Shown in the console as a level: **Read only**, **Read and write** or **Administer**. | `hookie:read`, `hookie:write`, `hookie:manage`; grant |
| **API key** | A credential (`hk_…`) for scripts and CI to call the admin API and `/mcp`, acting as the person who created it, capped at a role. Not an ingest key. | |
| **Plan** | Free, Pro or Team. See [Limits and plans](/concepts/limits-and-plans). | `standard` is Pro's internal ID |

## Getting events in

| Term | Meaning | Also appears as |
| --- | --- | --- |
| **Endpoint** | A public URL that receives events and stores them in one dataset. The URL is its credential. See [Endpoints](/concepts/endpoints). | `webhook` in admin API paths (`/webhooks`), MCP tools (`create_webhook`), fields (`webhook_id`) and some error messages; the **Webhook** project type; `hookie endpoints` in the CLI |
| **Endpoint URL** | `app.hookie.ai/{workspace}/{project}/{endpoint-slug}`. Shown as **Public URL** in the console. | `public_url`, `public_path` |
| **Endpoint slug** | The high-entropy last segment of an endpoint URL, generated by Hookie. It is the secret. | `webhook_slug`, `slug` in the path-form URL. Not `base_slug`, which is a readable label |
| **Ingest key** | A credential (`ik_live_…`) your own servers send events with. It can route with rules, require a signature and read the live stream. | `key` in `/v1/ingest/{key}` |
| **Signature verification** | An endpoint's check of the signature its provider adds to each request, such as Stripe's or GitHub's. | `verification` |
| **Activity** | An endpoint's log of what it received and refused over the last 7 days. | rejection log |
| **Event** | One accepted request to an endpoint or ingest key. Events are what the monthly event allowance counts. | |
| **Submission** | The body of an event exactly as it arrived, stored before any routing. | |
| **Source** | A database or HTTP feed that Hookie polls for new rows, on the **Connections** tab. | source connector |
| **Trigger** | Something that starts work without an inbound request. There are three kinds: **AI triggers** run a model when a record lands; **cron triggers** send an event on a schedule; **WebSocket triggers** send an event when a feed's message matches. | `triggers` (AI triggers only), `cron-triggers` and `ws-triggers` in the admin API; MCP tools `list_triggers` (AI triggers only), `list_cron_triggers` and `list_ws_triggers` |

## Storing and routing

| Term | Meaning | Also appears as |
| --- | --- | --- |
| **Dataset** | A named set of records, like a table. It exists once the first record lands in it. See [Datasets](/concepts/datasets-and-records). | |
| **Record** | One routed, stored row in a dataset. | event, in search (`search/events`) and MCP (`search_events`) |
| **Record view** | A saved set of columns for a dataset. | view |
| **Rule** | Routes keyed events with no dataset in the path into datasets, by conditions, and reshapes them with mappings. See [Rules](/concepts/rules-and-mappings). | mapping rule |
| **Condition** | A test on one field of a payload, such as `type` equals `refund`. On an endpoint, its conditions are called **criteria**. | `criteria` |
| **Mapping** | A field copied from the payload into the record, under a key you choose. | |

## Sending events out

| Term | Meaning | Also appears as |
| --- | --- | --- |
| **Destination** | An HTTPS URL of yours that Hookie sends records to, signed. Never called an endpoint in these docs. See [Destinations](/concepts/destinations-and-deliveries). | outbound webhook |
| **Delivery** | One record sent to one destination, with all of its attempts. | |
| **Attempt** | One try at a delivery. A delivery gets up to eight, and every one is kept. | |
| **Retry** | An automatic later attempt after a failure. | |
| **Replay** | Sending a delivery that did not arrive again, as a new delivery. | |
| **Held delivery** | A delivery waiting because the monthly delivery allowance is used up. Sent with **Send held deliveries**. | delivery hold |
| **Delivery allowance** | How many deliveries your plan includes each month. | delivery quota |
| **Signing secret** | The destination's secret (`whsec_…`) that signs each delivery. An ingest key that requires signatures has a signing secret of its own. | |
| **Live stream** | A real-time tail of a project's events over SSE or WebSocket. See [Live streaming](/streaming). | `stream` |

## Acting on events

| Term | Meaning | Also appears as |
| --- | --- | --- |
| **Workflow** | A multi-step pipeline that runs when a record lands in its entry dataset, including records made by a cron or WebSocket trigger. See [Workflows](/workflows). | |
| **Workflow run** | One execution of a workflow. | `instance`, `workflow-instances` in the admin API |
| **AI agent** | A reusable model, system prompt and optional memory dataset that a workflow calls with an `agent_call` step. Not related to connected agents. | `ai-agents` in the admin API |
| **Customer portal** | A page where *your* customers manage their own destinations and see their own deliveries. See [Customer portal](/customer-portal). | `portals` |
| **Portal token** | A per-customer credential (`hpt_…`) for a customer portal. | |

## Names to avoid

- Don't call a destination an "endpoint". An endpoint always receives; a destination always sends.
- Don't call an endpoint a "webhook" in prose. Use "webhook" for the general idea of an HTTP callback, and in API paths and tool names that already carry it.
- Don't say "agent" alone. Say **connected agent** for an OAuth coding agent, or **AI agent** for a workflow's model and prompt. Hookie has no built-in assistant.
- Don't say "trigger" alone when the kind matters. Say AI trigger, cron trigger or WebSocket trigger.
